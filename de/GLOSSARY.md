# Glossar

**Version:** v0.1  
**Stand:** 09.09.2026  
**Veröffentlicht:** 11.09.2026
**Autorin:** Nicole Bremicker · Y-Intelligence

Die folgenden Definitionen gelten innerhalb des **Y-I Referenzmodells für Agent Governance**. Sie ersetzen keine institutionellen oder rechtlichen Begriffsbestimmungen.

| Begriff | Bedeutung |
|---|---|
| **Agentenrolle** | Identifizierbare organisationale Funktion; ihre versionierte Spezifikation beschreibt Zweck und geregelte Beziehungen. |
| **Mandat** | Befugter organisationaler Akt beziehungsweise dessen nachvollziehbare Festlegung, der Auftrag, Befugnisse, Grenzen und Verantwortungsbeziehungen bestimmt. |
| **Aufgabe / Task** | Konkreter Arbeitsauftrag mit Gegenstand, angestrebtem Ergebnis und Bedingungen. |
| **Authority / Befugnis** | Normative Handlungs- oder Entscheidungsbefugnis aufgrund einer anwendbaren organisationalen Berechtigungsgrundlage. |
| **Effective Authority** | Unter den aktuellen Aufgabenbedingungen gültiger Teil dieser Befugnis. Sie bezeichnet keine technische Handlungsmöglichkeit. |
| **Decision Legitimation** | Frage nach der begründbaren Zulässigkeit einer konkreten Entscheidung und ihrer Umsetzung unter passenden Befugnissen und Bedingungen. |
| **Kontext / Context Sufficiency** | Kontext ist die aufgabenbezogene Informationsgrundlage. Context Sufficiency verlangt zugleich epistemische Hinlänglichkeit – genug Information für die konkrete Aussage – und Governance-Zulässigkeit ihrer Verwendung. |
| **Runtime-Instanz** | Konkreter Ausführungskontext aus wirksamem Modell, steuernder Software, Sitzung, technischer Identität und relevanten Diensten. |
| **Harness** | Software, die Modellaufrufe, Werkzeuge, Zustände und Ausführung steuert; Bestandteil beziehungsweise Vermittler der Runtime. |
| **Runtime Binding** | Explizite Zuordnung einer Instanz zu einer Rollen-Version und Aufgabe unter bestimmten Bedingungen. |
| **Qualification / Qualifikation** | Begründete, zeit- und aufgabenbezogene Beurteilung, ob die Runtime die erforderlichen Fähigkeiten und Governance-Bedingungen erfüllt. |
| **Approval Presentation** | Sichtbare Darstellung einer Bestätigung. Ihre Bedeutung hängt davon ab, was bestätigt wird und wozu die bestätigende Stelle befugt ist. |
| **Effective Grant** | Technisch wirksame Berechtigung, etwa eine von einem Dienst akzeptierte Zugriffserlaubnis. |
| **Effective Review Path** | Tatsächlich durchlaufener Prüfweg, einschließlich übersprungener oder aus früherer Prüfung übernommener Anteile. |
| **Governance Transition** | Änderung einer governance-relevanten Beziehung oder Bedingung, beispielsweise Befugnis, Kontextzugriff, Bindung oder Kontrolle. |
| **Governance-Handoff** | Governance Transition, bei der Aufgabe, Zuständigkeit oder Kontrolle zwischen Beteiligten übergeben wird. Nicht jede Transition hat einen Empfänger. |
| **Execution Evidence / Ausführungsnachweise** | Nachweise über die Ausführung und relevante Bedingungen, die eine bestimmte Governance-Frage beurteilen helfen. |
| **Accountability / Rechenschaft** | Beziehung zwischen einem erklärungspflichtigen Akteur und einem Forum, das Erklärung verlangen, beurteilen und Folgen veranlassen kann. |
| **Geschützte Wirkung** | Eine betrachtete Folge, für die bestimmte Autorisierungs- oder Kontrollbedingungen gelten; im konstruierten Fall die externe Nachricht. |
| **Assurance Scope / Nachweisumfang** | Ausdrücklich abgegrenzte Wirkungen, Komponenten, Zeiträume und Konfigurationen, auf die sich eine Prüfaussage bezieht. |
| **Nahtstelle** | Beziehung, an der unterschiedliche Darstellungen derselben Governance-Anforderung zusammenpassen müssen. |
